# Update history and the model's scores

Generated by `scripts/history_sensitivity.py` in 93 s on the 2025 test period (194,140 approaches, model `20251225-feaaf72`). Data from Space-Track.org (USSPACECOM).

Four of the model's inputs per object describe its recent update history (records in the last 30 days, largest and median orbit jump between records, median gap between records). Training used every element set Space-Track published. Live runs see only the snapshots our job took, so these inputs change; this shows how much, by rebuilding them as a snapshot job would have seen them and rescoring the same test approaches.

## What this means

- Thin history changes the model's **inputs**, not only a label: with one snapshot every object looks as if it had one record and no orbit changes, and the estimates shift with it (see the tables).
- Snapshot cadence barely matters: every 2 h or every 6 h over 30 days scores like the full history. A short collection window matters: compare the 7- and 15-day rows with the observed rates.
- The API marks every response from a run with under 25 days of snapshots (`history_complete: false`) and every estimate in it as provisional; the app shows that next to each estimate.
- Publishing in CI must pull 30 days of snapshots first (`python -m src.ops.archive_sync pull --history-days 30`).
