# The mobile app

Perigee installs on a phone in two ways. Both open the same live site, so new data and
almost every code change reach the app with no new download:

- **Home-screen app (PWA)**, Android and iPhone: open the site in the phone's browser,
  then *Install app* (Chrome) or *Share → Add to Home Screen* (Safari).
- **Android APK**: `perigee.apk`, a Trusted Web Activity (Chrome showing the site full
  screen as an app, with its own icon, splash screen and notifications).

The installed app gets a **phone layout** (`web/src/mobile/`): the globe fills the
screen, a bottom bar switches between *Globe, Approaches, Search, Risk, Settings*, and
details open in sheets and pages. The website keeps the dashboard, on phones too.
`src/pwa.ts` decides at load: installed (standalone display, the APK, or iOS home
screen) on a touch or narrow screen. `?app=1` shows the app layout in any browser
(the installed app's start URL; handy for previewing on a computer), `?app=0` the
dashboard.

## What is in the app

| Screen | What it does |
|---|---|
| Globe | The 3D globe (same as the dashboard: workers, smooth motion, NASA imagery), a top bar with the LIVE/FORECAST badge, whole-Earth and layers buttons, a time bar (play, speed, slider with "now", back to live) and a card for what is selected: an object, a close approach or a simulation |
| Approaches | Close approaches as cards with sort and filter chips; more load as you scroll; a card opens the detail in a sheet (*Show on globe*, *Watch*, *Share*) |
| Search | Results as you type, suggestions, the watch list; an object's page with its orbit, data age and approaches |
| Risk | Risk by altitude, and the breakup simulator (its debris shows on the globe) |
| Settings | Earth quality (High, Balanced, Battery saver), colours and object types on the globe, UTC or local times, notifications and the watch list, data facts, check for new data, clear saved data, method and limits, the full dashboard |

Smoothness: the globe stays loaded under every screen and stops drawing while it is
covered, so lists scroll at full speed and the globe is instant when you come back.
Screens keep their state and scroll position. Pull down on any screen to check for new
data. The Android back button closes a sheet, then returns to the globe, then leaves.

## Offline and updates

`web/public/sw.js` (the service worker, production builds only) keeps:

- the app and its data (network first: the newest when online, the saved copy offline);
- the hashed app files, Cesium and the simulator's Python (saved on first use);
- up to 800 NASA imagery tiles.

A new deployment is picked up on the next launch (the page is fetched fresh). If a new
daily snapshot is published while the app is open, it offers *Refresh*.

## Notifications

No server and no account: everything runs on the phone.

- **New data each day**: when the app opens on a new snapshot; also about once a day in
  the background where the phone allows it (periodic background sync: installed apps
  in Chrome on Android).
- **Watched objects**: when the app opens on a new snapshot, for each watched object
  with an approach in the next 72 h closer than 1 km or with an elevated risk estimate.

Instant push alerts (when the app is closed) need a small server and are a later step.

## Icons

From the artwork in `web/brand/icon-source.webp`: `python scripts/make_icons.py`
(needs `pip install pillow`) writes `web/public/icons/` (192/512, maskable for Android's
shaped icons, the Apple touch icon, favicons, the in-app logo and the notification
badge). The Android project has its own copies in `android/app/src/main/res/`:
regenerate the project (below) after changing the icon.

## The Android app

`android/` was generated by Google's Bubblewrap (`twa-manifest.json` records the
settings): package `io.github.aryanpol73.perigee`, start URL `/?app=1`, notifications
delegated to the app, minimum Android 7.0. The site proves the app is its own with
`web/public/.well-known/assetlinks.json` (the signing key's SHA-256 fingerprint);
without it Android would show a browser address bar on top.

### Signing key

The release key was created once on the development machine and lives outside the
repository, in `%USERPROFILE%\.perigee-android\`:

- `perigee-release.jks`, the key (alias `perigee`);
- `keystore-password.txt`, its password.

**Back both files up** (a password manager or an encrypted drive). Every update of the
app must be signed with the same key: if it is lost, phones cannot update the app and
users would have to uninstall it. Never commit them or paste them anywhere.

### Building on this machine

```powershell
powershell -ExecutionPolicy Bypass -File android\build-apk.ps1
```

Writes `android/dist/perigee.apk` (install on a phone) and `perigee.aab` (Google Play).
Needs JDK 17 and the Android SDK.

### Releases from GitHub (optional)

*Actions → android → Run workflow* with a version name (e.g. `1.1.0`) and a version
code higher than the last one. It builds, signs, checks the signature against
`assetlinks.json` and attaches the APK and the bundle to a GitHub release. It needs
two repository secrets (*Settings → Secrets and variables → Actions*), added once from
PowerShell on this machine, one value at a time (each command copies one value; paste
it into GitHub, never into a chat):

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("$env:USERPROFILE\.perigee-android\perigee-release.jks")) | Set-Clipboard
```

→ secret `ANDROID_KEYSTORE_BASE64`. Then:

```powershell
Get-Content "$env:USERPROFILE\.perigee-android\keystore-password.txt" -Raw | Set-Clipboard
```

→ secret `ANDROID_KEYSTORE_PASSWORD`. Afterwards clear the clipboard (copy any other text).

A new APK is only needed when the Android side changes (icon, name, colours, version);
site updates reach installed apps by themselves.

### Regenerating the project

After changing the icon, name or colours: install `@bubblewrap/cli`, edit
`android/twa-manifest.json`, run `bubblewrap update` in `android/`, then put back the
signing and version blocks in `android/app/build.gradle` (marked "Perigee").
